# Tests

Tests prove the bridge's contracts at the layer that can observe them. Unit tests sit next to their source files and cover pure policy: classification, the request lifecycle, wake decisions, rendering and secret checks, `ts` comparison, caller resolution, and presenters. The suites here cover what only a running bridge can show.

- `integration/` runs the bridge against protocol fakes of Socket Mode, the Slack Web API, and Toy Box, with no network, ephemeral ports, and temp folders. A suite spawns the real bridge process when it proves startup, shutdown or wiring, and drives the bridge's server modules in-process when it injects a clock or short timings. To prove what `serve` and `add-app` ask the owner, a suite runs them at a terminal of their own under macOS's `script`, which shows the test everything the terminal shows. To prove the CLI npm installs, a suite builds the binary with `bun run build` into a temp folder and runs it through its launcher in a lead's shell, where `BUN_BE_BUN` is set. A spawned bridge finds the fake Toy Box through `TOY_BOX_URL` and takes shorter waits from `TOY_BOX_SLACK_WAKE_TIMINGS`, a JSON object of the wake timings to change, in milliseconds. `bun test` runs it with the unit tests.
- `e2e/` runs the built Toy Box with a real Copilot lead on claude-sonnet-5, the real bridge and CLI, and fake Slack. Every run spends model credits, so it runs only when `TOY_BOX_SLACK_E2E=1` is set, as in `TOY_BOX_SLACK_E2E=1 bun test tests/e2e`, and one run at a time, because Toy Box takes port 3199.
- `fakes/` holds the protocol-faithful fakes both suites share. A fake reproduces what the real service does on the wire, including its failures, and nothing more.

An end-to-end run starts Toy Box under a temp `HOME`, so its database, sessions, skills and Copilot state never touch the owner's. Before Toy Box starts, the CLI under test goes on its `PATH` and the skill goes in that `HOME` where `serve` installs an owner's, since the lead adds its routine before the bridge first serves. It drops the variables agent shells set, which point at the owner's Toy Box, session and credentials, and its Copilot CLI signs in with the token from `gh auth token`, which goes only into Toy Box's environment. It runs the Toy Box built in the `toy-box` checkout beside this repository's main checkout, or the binary `TOY_BOX_BINARY` names. The bridge runs `serve` under the same `HOME` against fake Slack, so the lead's commands reach it, and it wakes the lead through that Toy Box a second after a request changes. The owner's setup is real too: the harness sets a passphrase, then links the channel and allows Alice with the CLI at a terminal, typing the passphrase on stdin. A second lead shares that Slack channel through an app of its own, which the owner adds with `add-app` at a terminal and serves by restarting the bridge, as the operations guide says. The lead adds the skill's routines with their prompts as written, so the scenarios prove the prompts leads get. A test channel's purpose rules out members, tasks and wakes its lead schedules, and a test wakes the lead only as the owner, with a routine run or through the bridge, once its last turn has settled. Assert what the lead did through `bridge.db`, the fakes and its presence, never its words. A failed run keeps its folder, without the Copilot CLI's unpacked caches, and names the lead's transcript and the tail of Toy Box's and the bridge's logs.

Nothing `bun test` runs reaches real Slack, so the live check runs by hand in the real test workspace with the test app. Make the package with `bun run build` and `npm pack`, install that tarball in place of the published one, and follow the README's Set up through the new mention it ends with. Try whatever the change touched too, and post the results to the Toy Box channel.

`startFakeSlack()` in `fakes/slack` serves the Web API and Socket Mode on a loopback port. Its existing controls belong to the default app. `addApp(identity?)` adds an app with its own tokens, installation, failures and sockets. Apps in a workspace share people, and apps joined to a channel share its messages. `app.addChannel({ id })` joins an existing channel, with `is_member` belonging only to that app. Seeding a channel, person or message changes stored state only. `broadcastEvent(event)` sends a channel event to every connected member app, once per app, sharing deliveries between that app's sockets. Web API posts and deletes do that automatically. App-local `sendEvent` and `sendFrame` target one app for fault tests. Set a fact to `undefined` to omit it from a response. Cleanup fails on any unknown method, argument or ack, including an ack from another app. `live.test.ts` pins the supported post, reply, history and deletion transcript to `live-shapes.json`, captured in the real test workspace, through both Slack SDKs. The fake models the bridge's API subset, not updates, broadcast writes, Slack's rate-limit schedule or reply-user sampling. Fake-only tests pin what product suites can't see, such as strict cleanup, decimal bounds and cursor scope, rather than repeat product cases. Disable SDK retries when asserting a single attempt. Time bounds are explicit, with no implicit current-time cutoff.

Give every test its own data folder and close every database it opens.
